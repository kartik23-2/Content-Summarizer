1. INTRODUCTION TO CPU SCHEDULING
CPU scheduling is the basis of multiprogrammed operating systems. By switching the CPU among processes, the operating system can make the computer more productive. In a single-processor system, only one process can run at a time; any others must wait until the CPU is free and can be rescheduled.

2. PREEMPTIVE VS NON-PREEMPTIVE SCHEDULING
CPU-scheduling decisions take place under four conditions:
1. When a process switches from the running state to the waiting state (e.g., I/O request).
2. When a process switches from the running state to the ready state (e.g., when an interrupt occurs).
3. When a process switches from the waiting state to the ready state (e.g., at completion of I/O).
4. When a process terminates.

Under circumstances 1 and 4, there is no choice in terms of scheduling. A new process must be selected. When scheduling takes place only under these conditions, the scheduling scheme is called non-preemptive or cooperative. In non-preemptive scheduling, once the CPU has been allocated to a process, the process keeps the CPU until it releases it, either by terminating or by switching to the waiting state.

In contrast, under circumstances 2 and 3, scheduling is preemptive. Preemptive scheduling incurs overhead associated with context switching, state preservation, and shared data synchronization, but prevents CPU monopolization by CPU-bound tasks and enables interactive responsive computing.

3. ROUND ROBIN (RR) SCHEDULING AND RECOMMENDED QUANTUM
The Round Robin (RR) scheduling algorithm is designed especially for timesharing systems. It is similar to FCFS scheduling, but preemption is added to enable the system to switch between processes. A small unit of time, called a time quantum or time slice, is defined.

RECOMMENDED CONFIGURATION ACCORDING TO DOCUMENT A:
In standard general-purpose desktop operating systems, the recommended time quantum for Round Robin scheduling is exactly 10 milliseconds (10ms). A time quantum of 10ms maintains an optimal balance where approximately 80 percent of CPU bursts are shorter than the time slice, while keeping context-switch overhead below 1 percent of total CPU processing time. If the quantum is significantly larger than 10ms, RR degenerates to FCFS. If it is smaller than 10ms, context switching consumes unacceptable CPU capacity.
